# 预算、取消与检查点恢复｜内容大纲

从一项需要多次查证的资料查询展开：Agent 已取得部分证据，但达到预算或收到取消。系统需要保存已发生的事实、停止后续动作，并说明哪些边界能够恢复。

对应正文：[让自主执行保持有界：预算、取消与检查点恢复](../06-budgets-cancellation-recovery.md)。

## 01｜查询还未结束，系统为什么需要主动停止？

用调用次数耗尽、单工具超时、用户取消和进程退出四种场景建立问题。区分用户任务完成与运行尝试结束。

## 02｜运行预算具体包含哪些数值？

展示 SDK turns、模型次数、工具次数、工具并发、Run 总时限、结果字节和上下文预算。解释每个参数的计量单位与执行位置，引用版本特定默认值。

## 03｜预算怎样进入本次 Run？

追踪 RunSnapshot、budgetFor 和 RunEnvironment。区分服务配置、运行快照与运行中计数。说明单次 Run 预算与整个 Turn 的累计成本不是同一个账户。

## 04｜并发工具怎样共享预算？

解释调用前预留、并发上限与执行总量。展示多个 ToolCall 同时到达时的合法动作范围，强调预算检查应位于真实动作边界。

## 05｜Deadline、Timeout 和租约有效期有什么区别？

分别解释 Run 总期限、工具期限、HTTP 观察时间、数据库租约和心跳。用一条时序图展示它们可以同时存在，观察超时不等于取消任务。

## 06｜AbortController 和 AbortSignal 长什么样？

展示取消控制器、信号合并、取消原因和调用前后检查。提供本地可运行的取消传播示例，说明协作式取消无法撤回已发生的远端效果。

## 07｜取消请求怎样从 HTTP 到达 Worker？

沿持久 cancel_requested、本地快速通知、心跳读回与 cancelled 收尾。解释 request 与 acknowledgement 的不同完成条件。

## 08｜模型完成与取消并发时谁决定终态？

读取 finishModelStep 和 finishRun 的状态锁。设计取消先提交、模型晚到的可重复竞争测试，核对已保存内容与终态事件。

## 09｜失败、中断、取消和结果未知怎样区分？

展示 failureCode 与 Run/Invocation 状态映射。说明 partial 内容、用量和证据继续保留；预算耗尽不保证有额外模型预算生成漂亮的总结。

## 10｜Retry 与 Resume 分别创建什么？

展示新 Run、同一 Turn、retryOfRunId、resumesRunId 和 checkpointId。核对最后未完成回合限制与当前版本条件。

## 11｜Checkpoint 包含哪些数据？

展示公开检查点摘要、内部引用状态、SDK 版本和工具集合身份。说明可序列化、可解析与可安全恢复是三种不同条件。

## 12｜三种恢复边界各恢复什么？

逐一解释 turn_boundary、tool_result_boundary 和 sdk_state。明确当前回合起点与工具结果复用的语义，避免把任何边界描述为任意 token 级继续。

## 13｜SDK 状态怎样经过恢复准入？

读取 inspectSdkCheckpoint：格式版本、服务端会话所有权、未完成 Session 写入、上下文和已提交历史。展示 recoverable=false 的原因和保留事实策略。

## 14｜工具已返回、结果未提交时怎么办？

画出外部效果与本地提交的窗口。说明 outcome_unknown、只读重查和未来写工具所需的幂等/读回机制。已提交结果按原身份复用。

## 15｜Worker 退出和状态超限怎样收敛？

解释租约监督、旧 Fence 拒写、超大 SDK 状态与替代恢复边界。不同恢复模式分别报告能力，不使用笼统的恢复成功标志。

## 16｜怎样验证预算、取消和恢复？

提供故障矩阵、同步屏障、运行前后数据读取与测试命令。检查没有超预算新动作、终态一致、新 Run 关联和已完成调用复用。
