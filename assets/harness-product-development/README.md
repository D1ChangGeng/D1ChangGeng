## 从通用接口看完整产品

```text
用户操作 / 外部系统请求
  → HarnessClient（业务客户端）
  → Harness API：创建、发送、等待、查询、订阅、控制、历史、产物
  → 可信控制与任务生命周期
  → 执行引擎适配器
  → 模型、上下文、工具和实际执行环境
  → 权威事实、状态、检查点和结果
  → 展示投影与可恢复客户端同步
  → 桌面 / 命令行 / 网页体验
```

读者应能从每个产品行为定位到一个公共能力，再追踪其内部责任、数据与验证证据。

## 首先确认的五项决定

采用本指南开展项目时，先明确目标用户路径、运行部署、首个验收平台、工具权限模式和恢复范围。

例如，本地双端配置可以由一个常驻后台统一管理任务，桌面和命令行控制同一个执行；远程配置则把同一接口放在已认证服务端，并扩展租户、资源调度和运行环境。两者共享业务语义，能力与安全保证分别声明。

## 本指南重点确定的边界

**提交、等待与执行：**同步等待可以持续到指定执行尝试形成处理结果；连接时限、调用方等待期限、任务预算和工具超时分别定义。

**任务与尝试：**停止结束当前尝试，合法继续建立新尝试；旧等待者仍能取得原尝试结果。

**事实与展示：**模型调用、工具执行和任务状态由权威记录确定，UIMessage 等界面消息格式通过适配层承载展示。

**历史与外部环境：**编辑和对话分支保持可追溯，工作区回滚按独立权限及版本规则处理。

**模块与交付：**模块按依赖顺序建立，每一阶段通过完整用户路径和证据进入下一阶段。

## 阅读路径

准备整体架构时，先读指南第 1—5 节和第 17—18 节，再选择部署配置。

准备实现接口与执行时，重点阅读指南第 6—13 节及 API 附录，并把约定转为运行时校验和契约测试。

准备接入桌面或 CLI 时，阅读指南第 13—16 节，并先验证共享客户端的快照、游标和控制行为。

准备安排开发时，直接使用路线附录建立阶段任务，以不变量和用例编号关联实现与验收。

## 范围与版本说明

文中的 Harness、Thread（业务会话）、Turn（任务轮次）、RunAttempt（执行尝试）和 ModelStep（模型调用）是参考建模约定。采用现有框架时，应映射其实际语义并保留可观测能力边界。

接口样例、状态、默认值和性能指标是设计参考。验收矩阵供项目实际执行；发布本文不表示某个 Agent 系统已经完成实现、安全验证或部署。

在线技术资料可能随版本变化。项目应保存依赖锁文件、协议版本、平台配置和真实测试证据，尤其是 SDK 取消与恢复、界面流协议、权限隔离和升级行为。
